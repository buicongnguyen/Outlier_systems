1. Algorithm classics

Q1. Two Sum

easyhash map

The "hello world" of coding interviews — first problem in Blind 75; still used as a warm-up screen everywhere.

Given an array of integers nums and an integer target, return the indices of the two numbers that add up to target. Exactly one solution exists; you may not use the same element twice. Example: nums=[2,7,11,15], target=9 → [0,1].

Approach

One pass with a hash map from value → index. For each number, check whether its complement (target - num) has already been seen. The brute force compares all pairs in O(n²); the map trades O(n) space for one lookup per element.

def two_sum(nums, target):
    # 1) Remember each previously visited value and its index.
    seen = {}

    # 2) For the current value, look backward for its complement.
    for i, num in enumerate(nums):
        want = target - num
        if want in seen:
            # 3) The stored index is different because insertion happens later.
            return [seen[want], i]

        # 4) Make this value available to later elements; no self-pairing.
        seen[num] = i

    raise ValueError("no two-sum solution")
#include <stdexcept>
#include <unordered_map>
#include <vector>

std::vector<int> twoSum(const std::vector<int>& nums, int target) {
    // 1) Map each previously visited value to its array index.
    std::unordered_map<int, int> seen;

    // 2) Search for the complement before storing the current value.
    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        const int want = target - nums[i];
        if (auto match = seen.find(want); match != seen.end()) {
            // 3) The stored element and current element form the answer.
            return {match->second, i};
        }

        // 4) Insert afterward so one element cannot match itself.
        seen[nums[i]] = i;
    }

    throw std::invalid_argument("no two-sum solution");
}
O(n) time, O(n) space

Pitfalls & follow-ups

Insert into the map after checking, or target = 2×num matches the element with itself. Follow-ups: input sorted (two pointers, O(1) space), find all pairs, or 3Sum below.

Q2. Find the Extra Character

easybit tricks / counting

Reported on Glassdoor for Google software-engineer screens: two strings with the same characters, one has a single extra.

String t is s shuffled plus one extra character. Return that character. Example: s="abcd", t="cbdae" → "e".

Approach

XOR every character code of both strings together: pairs cancel (x⊕x=0), leaving exactly the extra character. Equivalent one-liner: difference of summed character codes. Both beat the obvious Counter-diff on space.

def extra_char(s, t):
    # 1) Zero is the identity value for XOR.
    acc = 0

    # 2) Equal character codes cancel regardless of their shuffled order.
    for ch in s:
        acc ^= ord(ch)
    for ch in t:
        acc ^= ord(ch)

    # 3) Only the unmatched character code remains.
    return chr(acc)
#include <string>

char extraChar(const std::string& s, const std::string& t) {
    // 1) Zero is the identity value for XOR.
    unsigned char accumulator = 0;

    // 2) Every matching byte cancels with its copy in the other string.
    for (const unsigned char ch : s) {
        accumulator ^= ch;
    }
    for (const unsigned char ch : t) {
        accumulator ^= ch;
    }

    // 3) The one byte without a partner is the extra character.
    return static_cast<char>(accumulator);
}
O(n) time, O(1) space

Pitfalls & follow-ups

State the invariant (XOR is commutative, associative, self-inverse) — that's what is being tested. Follow-up: the same trick solves "single number" (every element appears twice except one) and "missing number in 1..n".

Q3. 3Sum — Unique Triplets Summing to Zero

mediumsorting + two pointers

Reported on Glassdoor for Meta/Google onsites; a Blind 75 staple with a famous duplicate-handling trap.

Given an integer array, return all unique triplets [a,b,c] with a+b+c=0. Example: [-1,0,1,2,-1,-4] → [[-1,-1,2],[-1,0,1]].

Approach

Sort, then for each anchor index run two pointers over the remainder looking for -anchor. Sorting makes duplicate-skipping possible: advance past equal values at the anchor and at both pointers after each hit.

def three_sum(nums):
    # 1) Sorting enables a two-pointer scan and adjacent duplicate checks.
    nums.sort()
    result = []

    # 2) Fix one value as the anchor of each candidate triplet.
    for i in range(len(nums) - 2):
        if i > 0 and nums[i] == nums[i - 1]:
            continue  # This anchor would reproduce earlier triplets.
        if nums[i] > 0:
            break  # All remaining values are positive.

        # 3) Move two pointers according to whether the sum is low or high.
        left, right = i + 1, len(nums) - 1
        while left < right:
            total = nums[i] + nums[left] + nums[right]
            if total < 0:
                left += 1
            elif total > 0:
                right -= 1
            else:
                result.append([nums[i], nums[left], nums[right]])

                # 4) Skip equal pointer values before searching again.
                while left < right and nums[left] == nums[left + 1]:
                    left += 1
                while left < right and nums[right] == nums[right - 1]:
                    right -= 1
                left += 1
                right -= 1

    return result
#include <algorithm>
#include <vector>

std::vector<std::vector<int>> threeSum(std::vector<int> nums) {
    // 1) Sort a copy so duplicates are adjacent and pointers are monotonic.
    std::sort(nums.begin(), nums.end());
    std::vector<std::vector<int>> result;

    // 2) Fix one anchor, then solve a two-sum problem to its right.
    for (int i = 0; i + 2 < static_cast<int>(nums.size()); ++i) {
        if (i > 0 && nums[i] == nums[i - 1]) continue;
        if (nums[i] > 0) break;

        int left = i + 1;
        int right = static_cast<int>(nums.size()) - 1;

        // 3) Increase a low sum from the left or decrease a high sum.
        while (left < right) {
            const long long total =
                static_cast<long long>(nums[i]) + nums[left] + nums[right];
            if (total < 0) {
                ++left;
            } else if (total > 0) {
                --right;
            } else {
                result.push_back({nums[i], nums[left], nums[right]});

                // 4) Skip duplicates so every emitted triplet is unique.
                const int leftValue = nums[left];
                const int rightValue = nums[right];
                while (left < right && nums[left] == leftValue) ++left;
                while (left < right && nums[right] == rightValue) --right;
            }
        }
    }

    return result;
}
O(n²) time, O(1) extra space (beyond sort/output)

Pitfalls & follow-ups

The interview is really about the three duplicate-skips — a set-of-tuples dedupe works but signals brute force. Follow-ups: 3Sum-closest, 4Sum (one more anchor loop), k-Sum recursion.

Q4. Merge Overlapping Intervals

mediumsorting / sweep

Blind 75 interval category; constantly reported across Glassdoor for calendar/booking-flavored screens.

Given intervals [[1,3],[2,6],[8,10],[15,18]], merge all overlapping ones → [[1,6],[8,10],[15,18]].

Approach

Sort by start. Sweep left to right keeping the last merged interval: if the next start fits inside it (start ≤ last_end), extend the end with max; otherwise emit a new interval. Sorting is what turns "compare everything with everything" into one linear pass.

def merge(intervals):
    # 1) Ordered starts guarantee only the last merged interval can overlap.
    intervals.sort(key=lambda interval: interval[0])
    merged = []

    # 2) Sweep once from the earliest start to the latest.
    for start, end in intervals:
        if merged and start <= merged[-1][1]:
            # 3) Grow the current interval; max preserves a containing interval.
            merged[-1][1] = max(merged[-1][1], end)
        else:
            # 4) A gap starts a new disjoint interval.
            merged.append([start, end])

    return merged
#include <algorithm>
#include <vector>

std::vector<std::vector<int>> mergeIntervals(
    std::vector<std::vector<int>> intervals) {
    // 1) Lexicographic vector ordering sorts by start, then end.
    std::sort(intervals.begin(), intervals.end());
    std::vector<std::vector<int>> merged;

    // 2) Only the latest merged interval can overlap the next one.
    for (const auto& interval : intervals) {
        if (!merged.empty() && interval[0] <= merged.back()[1]) {
            // 3) Preserve the farther end when one interval contains another.
            merged.back()[1] = std::max(merged.back()[1], interval[1]);
        } else {
            // 4) No overlap means this begins a new output interval.
            merged.push_back(interval);
        }
    }

    return merged;
}
O(n log n) time, O(n) output

Pitfalls & follow-ups

The max() is the classic bug: [1,10],[2,3] must stay [1,10]. Clarify whether touching intervals ([1,2],[2,3]) merge. Follow-ups: insert-interval into a sorted list, minimum meeting rooms (heap of end times).

Q5. Validate a Binary Search Tree

mediumtrees / recursion

Reported on Glassdoor for Google ("decide if the given binary tree is a BST"); a canonical recursion-with-invariants test.

Return true iff the tree is a valid BST: every node in a left subtree is less than its ancestor node, every node in a right subtree greater — not just the immediate children.

Approach

Pass down the open interval each node must fall in: root gets (-∞, +∞); going left tightens the upper bound, going right the lower. Alternative with the same power: an in-order traversal of a BST must be strictly increasing.

def is_bst(node, low=float("-inf"), high=float("inf")):
    # 1) An empty subtree satisfies every inherited bound.
    if node is None:
        return True

    # 2) Validate against all ancestors, not only the parent.
    if not (low < node.val < high):
        return False

    # 3) The current value becomes the tighter bound for each child.
    return (is_bst(node.left, low, node.val) and
            is_bst(node.right, node.val, high))
#include <limits>

struct TreeNode {
    int value;
    TreeNode* left = nullptr;
    TreeNode* right = nullptr;
};

bool isBst(
    const TreeNode* node,
    long long low = std::numeric_limits<long long>::lowest(),
    long long high = std::numeric_limits<long long>::max()) {
    // 1) An empty subtree cannot violate the BST invariant.
    if (node == nullptr) return true;

    // 2) Long-long bounds safely sit outside every possible int value.
    if (!(low < node->value && node->value < high)) return false;

    // 3) Propagate every ancestor constraint into both subtrees.
    return isBst(node->left, low, node->value) &&
           isBst(node->right, node->value, high);
}
O(n) time, O(h) recursion stack

Pitfalls & follow-ups

The famous wrong answer checks only left.val < node.val < right.val — it accepts a grandchild that violates a grandparent's bound. Also decide how duplicates are treated (strict < here). Follow-ups: recover a BST with two swapped nodes; kth smallest via in-order.

Q6. Longest Increasing Subsequence

mediumDP / binary search

Reported on Glassdoor with the explicit ask to explain BOTH the O(n²) and O(n log n) solutions.

Length of the longest strictly increasing subsequence (not necessarily contiguous). Example: [10,9,2,5,3,7,101,18] → 4 (2,3,7,101).

Approach

DP: dp[i] = best LIS ending at i, looking back at all j<i — O(n²). Patience method: keep tails[k] = smallest possible tail of an increasing subsequence of length k+1; each element binary-searches its slot. tails stays sorted, its length is the answer.

def lis_quadratic(nums):
    # 1) dp[i] stores the best increasing subsequence ending exactly at i.
    dp = [1] * len(nums)
    for i in range(len(nums)):
        # 2) Extend every earlier subsequence whose tail is smaller.
        for j in range(i):
            if nums[j] < nums[i]:
                dp[i] = max(dp[i], dp[j] + 1)
    return max(dp, default=0)


from bisect import bisect_left

def lis_nlogn(nums):
    # 1) tails[k] is the smallest tail found for length k + 1.
    tails = []
    for value in nums:
        # 2) Replace the first tail >= value, keeping tails sorted.
        index = bisect_left(tails, value)
        if index == len(tails):
            # 3) No replacement means a longer subsequence now exists.
            tails.append(value)
        else:
            tails[index] = value
    return len(tails)
#include <algorithm>
#include <vector>

int lisQuadratic(const std::vector<int>& nums) {
    // 1) dp[i] is the best subsequence ending at index i.
    std::vector<int> dp(nums.size(), 1);
    int best = 0;

    // 2) Try extending every compatible earlier endpoint.
    for (int i = 0; i < static_cast<int>(nums.size()); ++i) {
        for (int j = 0; j < i; ++j) {
            if (nums[j] < nums[i]) dp[i] = std::max(dp[i], dp[j] + 1);
        }
        best = std::max(best, dp[i]);
    }
    return best;
}

int lisNlogN(const std::vector<int>& nums) {
    // 1) tails[k] keeps the minimum tail for subsequence length k + 1.
    std::vector<int> tails;

    for (const int value : nums) {
        // 2) lower_bound enforces strictly increasing subsequences.
        auto position = std::lower_bound(tails.begin(), tails.end(), value);
        if (position == tails.end()) {
            // 3) This value extends the longest length seen so far.
            tails.push_back(value);
        } else {
            // 4) A smaller tail leaves more room for future values.
            *position = value;
        }
    }
    return static_cast<int>(tails.size());
}
O(n²) / O(n log n) time

Pitfalls & follow-ups

tails is NOT the subsequence itself — only its length is meaningful (reconstructing needs parent links). bisect_left vs bisect_right is the strict-vs-non-strict switch. Follow-up: Russian doll envelopes = LIS after a sort trick.

Q7. Top K Frequent Elements

mediumhash map + heap

Blind 75 heap category; the "log analysis" screen question in countless Glassdoor reports.

Given an array and k, return the k most frequent elements. Example: [1,1,1,2,2,3], k=2 → [1,2].

Approach

Count with a hash map, then select. A size-k min-heap over (count, value) gives O(n log k) — the heap holds the current best k, and anything smaller than its root can't be top-k. Bucket sort by count reaches O(n): index buckets by frequency (at most n), walk from the top.

from collections import Counter
import heapq

def top_k(nums, k):
    # 1) Collapse repeated input values into (value, frequency) pairs.
    counts = Counter(nums)

    # 2) Keep only the k greatest pairs according to frequency.
    largest = heapq.nlargest(k, counts.items(), key=lambda pair: pair[1])

    # 3) The problem returns values, not their counts.
    return [value for value, _ in largest]


def top_k_bucket(nums, k):
    if k <= 0:
        return []

    # 1) A value can appear at most len(nums) times.
    counts = Counter(nums)
    buckets = [[] for _ in range(len(nums) + 1)]
    for value, frequency in counts.items():
        buckets[frequency].append(value)

    # 2) Read buckets from highest frequency downward until k values exist.
    result = []
    for frequency in range(len(buckets) - 1, 0, -1):
        for value in buckets[frequency]:
            result.append(value)
            if len(result) == k:
                return result
    return result
#include <functional>
#include <queue>
#include <unordered_map>
#include <utility>
#include <vector>

std::vector<int> topK(const std::vector<int>& nums, int k) {
    if (k <= 0) return {};

    // 1) Count every distinct value in one input pass.
    std::unordered_map<int, int> counts;
    for (const int value : nums) ++counts[value];

    // 2) Keep a min-heap of the best k (frequency, value) pairs.
    using Entry = std::pair<int, int>;
    std::priority_queue<Entry, std::vector<Entry>, std::greater<Entry>> heap;
    for (const auto& [value, frequency] : counts) {
        heap.emplace(frequency, value);
        if (static_cast<int>(heap.size()) > k) heap.pop();
    }

    // 3) Extract the retained values; their order is not significant.
    std::vector<int> result;
    while (!heap.empty()) {
        result.push_back(heap.top().second);
        heap.pop();
    }
    return result;
}

std::vector<int> topKBucket(const std::vector<int>& nums, int k) {
    if (k <= 0) return {};

    // 1) Group values by frequency; no frequency exceeds nums.size().
    std::unordered_map<int, int> counts;
    for (const int value : nums) ++counts[value];
    std::vector<std::vector<int>> buckets(nums.size() + 1);
    for (const auto& [value, frequency] : counts) {
        buckets[frequency].push_back(value);
    }

    // 2) Walk from the most frequent bucket until k values are collected.
    std::vector<int> result;
    for (int frequency = static_cast<int>(nums.size());
         frequency > 0 && static_cast<int>(result.size()) < k;
         --frequency) {
        for (const int value : buckets[frequency]) {
            result.push_back(value);
            if (static_cast<int>(result.size()) == k) break;
        }
    }
    return result;
}
O(n log k) heap / O(n) bucket

Pitfalls & follow-ups

Say why it beats full sorting (O(n log n) wastes work ordering elements you'll discard). Follow-ups: top-k in a stream (keep the k-heap), across sharded logs (local top-k, then merge — connects to the distributed section of this hub).

Q8. LRU Cache with O(1) Operations

mediumhash map + doubly linked list

Possibly the most-asked design-coding question anywhere (LeetCode 146); reported at Twitch, Meta, Amazon and dozens more on Glassdoor.

Design a fixed-capacity cache: get(key) returns the value or -1; put(key, value) inserts/updates and evicts the least recently used entry when full. Both must run in O(1) average time.

Approach

Recency order needs a sequence with O(1) move-to-front and remove-tail: a doubly linked list. Key lookup needs O(1): a hash map pointing at the list nodes. Every get/put unlinks the node and re-links it at the front; eviction pops the tail. Python's OrderedDict packages exactly this pair.

from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity):
        if capacity <= 0:
            raise ValueError("capacity must be positive")

        # 1) OrderedDict combines a hash map with a linked recency order.
        self.capacity = capacity
        self.entries = OrderedDict()  # front = oldest, end = newest

    def get(self, key):
        # 2) A miss does not change recency.
        if key not in self.entries:
            return -1

        # 3) A hit becomes the most recently used entry.
        self.entries.move_to_end(key)
        return self.entries[key]

    def put(self, key, value):
        # 4) Insert/update and mark the key as most recently used.
        if key in self.entries:
            self.entries.move_to_end(key)
        self.entries[key] = value

        # 5) Remove exactly one oldest entry when capacity is exceeded.
        if len(self.entries) > self.capacity:
            self.entries.popitem(last=False)
#include <cstddef>
#include <list>
#include <stdexcept>
#include <unordered_map>
#include <utility>

class LRUCache {
public:
    explicit LRUCache(std::size_t capacity) : capacity_(capacity) {
        if (capacity_ == 0) throw std::invalid_argument("capacity must be positive");
    }

    int get(int key) {
        // 1) The hash map finds the corresponding list node in O(1) average time.
        const auto found = index_.find(key);
        if (found == index_.end()) return -1;

        // 2) Move the hit to the front, which represents most recently used.
        entries_.splice(entries_.begin(), entries_, found->second);
        return found->second->second;
    }

    void put(int key, int value) {
        if (auto found = index_.find(key); found != index_.end()) {
            // 3) Update an existing node and refresh its recency.
            found->second->second = value;
            entries_.splice(entries_.begin(), entries_, found->second);
            return;
        }

        // 4) Insert new entries at the most-recent front of the list.
        entries_.emplace_front(key, value);
        index_[key] = entries_.begin();

        if (entries_.size() > capacity_) {
            // 5) The back is least recent; erase it from both data structures.
            index_.erase(entries_.back().first);
            entries_.pop_back();
        }
    }

private:
    using Entry = std::pair<int, int>;
    using Iterator = std::list<Entry>::iterator;

    std::size_t capacity_;
    std::list<Entry> entries_;              // front = newest, back = oldest
    std::unordered_map<int, Iterator> index_;
};
O(1) get / put, O(capacity) space

Pitfalls & follow-ups

If asked to build it raw: sentinel head/tail nodes remove all the null-pointer edge cases; a plain singly linked list fails (O(n) unlink). Follow-ups: thread-safety (one lock, or sharded locks), TTL entries, LFU (LeetCode 460 — count buckets), and "what does Redis actually do?" (approximate LRU sampling).

Q9. Bounded Blocking Queue (Producer–Consumer)

mediumconcurrency / condition variables

The staple concurrency interview (GeeksforGeeks, Hello Interview LLD); tests mutexes, condition variables, and spurious wakeups in one problem.

Implement a fixed-capacity queue for multiple producer and consumer threads: put() blocks while full, take() blocks while empty. No busy-waiting.

Approach

One mutex guards the buffer; two condition variables carry the two wait reasons (not_full for producers, not_empty for consumers). Waits sit in while loops re-checking the predicate — wakeups are hints, not guarantees — and each side signals the other side after mutating.

import threading
from collections import deque

class BoundedQueue:
    def __init__(self, capacity):
        if capacity <= 0:
            raise ValueError("capacity must be positive")

        # 1) One lock protects both the queue data and both wait predicates.
        self.buffer = deque()
        self.capacity = capacity
        self.lock = threading.Lock()
        self.not_full = threading.Condition(self.lock)
        self.not_empty = threading.Condition(self.lock)

    def put(self, item):
        with self.not_full:
            # 2) Recheck after every wakeup: another producer may win the slot.
            while len(self.buffer) == self.capacity:
                self.not_full.wait()

            # 3) Publish the item while holding the same predicate lock.
            self.buffer.append(item)
            self.not_empty.notify()  # A consumer may now make progress.

    def take(self):
        with self.not_empty:
            # 4) Sleep without busy-waiting until an item is truly available.
            while not self.buffer:
                self.not_empty.wait()

            item = self.buffer.popleft()
            self.not_full.notify()  # A producer may now make progress.
            return item
#include <condition_variable>
#include <cstddef>
#include <deque>
#include <mutex>
#include <stdexcept>
#include <utility>

template <typename T>
class BoundedQueue {
public:
    explicit BoundedQueue(std::size_t capacity) : capacity_(capacity) {
        if (capacity_ == 0) throw std::invalid_argument("capacity must be positive");
    }

    void put(T item) {
        std::unique_lock<std::mutex> lock(mutex_);

        // 1) The predicate handles spurious wakeups and competing producers.
        notFull_.wait(lock, [this] { return buffer_.size() < capacity_; });

        // 2) Mutate the queue while the predicate's mutex is held.
        buffer_.push_back(std::move(item));
        lock.unlock();

        // 3) Wake one consumer after publishing the new item.
        notEmpty_.notify_one();
    }

    T take() {
        std::unique_lock<std::mutex> lock(mutex_);

        // 4) Sleep efficiently until a producer makes the queue non-empty.
        notEmpty_.wait(lock, [this] { return !buffer_.empty(); });

        T item = std::move(buffer_.front());
        buffer_.pop_front();
        lock.unlock();

        // 5) The freed slot allows one producer to continue.
        notFull_.notify_one();
        return item;
    }

private:
    const std::size_t capacity_;
    std::deque<T> buffer_;
    std::mutex mutex_;
    std::condition_variable notFull_;
    std::condition_variable notEmpty_;
};
O(1) per operation; waiting threads sleep (no CPU burn)

Pitfalls & follow-ups

The three classic mistakes: if instead of while around wait; one shared condition with notify() (a producer can wake a producer — use two conditions or notify_all); signaling before releasing consistency. Follow-ups: implement with two semaphores (empty/full slots), poison-pill shutdown, and why unbounded queues break backpressure (ties to the distributed section).

Q10. Thread-Safe Token-Bucket Rate Limiter

mediumconcurrency / clocks

Standard at infra teams (AlgoMaster, Hello Interview, system-design blogs): "allow N requests/sec with bursts — implement it."

Implement allow() → bool: requests consume a token; tokens refill at rate per second up to capacity (burst size). Must be correct under concurrent callers.

Approach

Lazy refill: no background thread — on each call, compute tokens earned since the last refill from a monotonic clock, cap at capacity, then atomically check-and-decrement under a lock. The check and the decrement must be one critical section or two threads both pass on the last token.

import threading
import time

class TokenBucket:
    def __init__(self, rate, capacity):
        if rate <= 0 or capacity <= 0:
            raise ValueError("rate and capacity must be positive")

        # 1) Start full so the configured burst is immediately available.
        self.rate = rate
        self.capacity = capacity
        self.tokens = float(capacity)
        self.last_refill = time.monotonic()
        self.lock = threading.Lock()

    def allow(self):
        # 2) Refill, test and consume as one atomic state transition.
        with self.lock:
            now = time.monotonic()  # Monotonic time cannot jump backward.
            elapsed = now - self.last_refill

            # 3) Refill lazily and cap stored credit at burst capacity.
            self.tokens = min(
                self.capacity,
                self.tokens + elapsed * self.rate,
            )
            self.last_refill = now

            # 4) Admit only when a complete token can be consumed.
            if self.tokens < 1.0:
                return False
            self.tokens -= 1.0
            return True
#include <algorithm>
#include <chrono>
#include <mutex>
#include <stdexcept>

class TokenBucket {
public:
    TokenBucket(double rate, double capacity)
        : rate_(rate), capacity_(capacity), tokens_(capacity),
          lastRefill_(Clock::now()) {
        if (rate_ <= 0.0 || capacity_ <= 0.0) {
            throw std::invalid_argument("rate and capacity must be positive");
        }
    }

    bool allow() {
        // 1) Refill, test and consume while one lock protects bucket state.
        std::lock_guard<std::mutex> guard(mutex_);
        const auto now = Clock::now();

        // 2) steady_clock measures elapsed time and never follows wall-clock jumps.
        const double elapsed = std::chrono::duration<double>(now - lastRefill_).count();

        // 3) Lazy refill removes the need for a background timer thread.
        tokens_ = std::min(capacity_, tokens_ + elapsed * rate_);
        lastRefill_ = now;

        // 4) Consume one complete token or reject without changing the balance.
        if (tokens_ < 1.0) return false;
        tokens_ -= 1.0;
        return true;
    }

private:
    using Clock = std::chrono::steady_clock;

    const double rate_;
    const double capacity_;
    double tokens_;
    Clock::time_point lastRefill_;
    std::mutex mutex_;
};
O(1) per call, O(1) state per bucket

Pitfalls & follow-ups

Wall-clock time breaks on NTP jumps — use monotonic. Fractional tokens are fine (float); per-key buckets go in a dict (mind cleanup). Follow-ups: token bucket vs leaky bucket vs sliding window; distributed version (state in Redis, refill+decrement in one atomic Lua script — the same race, solved the same way).

Q11. Retry with Exponential Backoff and Jitter

easyreliability patterns

Asked as "make this API call robust" at AWS-style shops — the AWS Builders' Library pattern as a coding exercise.

Wrap a flaky function so it retries transient failures up to max_attempts times, waiting exponentially longer between tries, with randomized jitter, and a cap on the delay.

Approach

Delay for attempt n is random.uniform(0, min(cap, base × 2ⁿ)) — "full jitter". The exponential spreads load over time; the randomization decorrelates clients so a synchronized failure doesn't retry as a synchronized stampede.

import random
import time

def retry(fn, max_attempts=5, base=0.1, cap=10.0,
          retryable=(TimeoutError, ConnectionError)):
    if max_attempts <= 0 or base < 0 or cap < 0:
        raise ValueError("invalid retry policy")

    # 1) The loop count is the total attempt budget, not retry count.
    for attempt in range(max_attempts):
        try:
            return fn()
        except retryable:
            # 2) Surface the final transient failure when the budget is empty.
            if attempt == max_attempts - 1:
                raise

            # 3) Exponential growth is capped; full jitter spreads clients out.
            maximum_delay = min(cap, base * 2 ** attempt)
            delay = random.uniform(0, maximum_delay)

            # 4) Wait before the next attempt; production code also checks a deadline.
            time.sleep(delay)
#include <algorithm>
#include <chrono>
#include <exception>
#include <functional>
#include <random>
#include <stdexcept>
#include <thread>
#include <type_traits>
#include <utility>

template <typename Function, typename IsRetryable>
auto retry(Function&& function, IsRetryable&& isRetryable,
           int maxAttempts = 5,
           std::chrono::milliseconds base = std::chrono::milliseconds(100),
           std::chrono::milliseconds cap = std::chrono::seconds(10))
    -> std::invoke_result_t<Function&> {
    if (maxAttempts <= 0 || base.count() < 0 || cap.count() < 0) {
        throw std::invalid_argument("invalid retry policy");
    }

    std::mt19937_64 randomEngine(std::random_device{}());

    // 1) Count total attempts so the final failure has a precise boundary.
    for (int attempt = 0; attempt < maxAttempts; ++attempt) {
        try {
            return std::invoke(function);
        } catch (const std::exception& error) {
            // 2) Never retry permanent failures or exceed the attempt budget.
            if (!std::invoke(isRetryable, error) || attempt == maxAttempts - 1) {
                throw;
            }

            // 3) Double the ceiling safely until it reaches the configured cap.
            long long maximumDelay = std::min(base.count(), cap.count());
            for (int growth = 0; growth < attempt && maximumDelay < cap.count();
                 ++growth) {
                const long long remaining = cap.count() - maximumDelay;
                maximumDelay += std::min(maximumDelay, remaining);
            }

            // 4) Full jitter selects any delay from zero through that ceiling.
            std::uniform_int_distribution<long long> jitter(0, maximumDelay);
            std::this_thread::sleep_for(std::chrono::milliseconds(jitter(randomEngine)));
        }
    }

    throw std::logic_error("unreachable retry state");
}
Worst-case wait bounded by Σ min(cap, base·2ⁿ)

Pitfalls & follow-ups

Only retry transient errors (a 400 will fail forever; a timeout may have succeeded server-side — so the operation must be idempotent). Never retry without jitter. Follow-ups: honor an overall deadline instead of attempt count, retry budgets (retries as % of traffic), and where the circuit breaker takes over — this is the coding half of the retry-amplification postmortem in the distributed section.

Q12. Consistent Hashing Ring

mediumdistributed systems / binary search

The "design a cache cluster's key placement" question — asked wherever sharding is discussed; the algorithm inside Dynamo, Cassandra, and memcached clients.

Implement add_node, remove_node, and get_node(key) such that keys spread evenly and adding/removing a node remaps only ~1/N of keys (naive hash(key) % N remaps almost everything).

Approach

Hash nodes onto a circle (0..2³²); a key belongs to the first node clockwise from its own hash — a binary search over the sorted node-hash list. Each physical node gets many virtual nodes (replicas of its hash with different salts) so load spreads evenly and a leaving node's keys scatter to everyone, not one neighbor.

import bisect
import hashlib

def stable_hash(value):
    # 1) Use a process-independent hash so every client builds the same ring.
    data = value if isinstance(value, bytes) else str(value).encode()
    return int.from_bytes(hashlib.sha256(data).digest()[:4], "big")


class HashRing:
    def __init__(self, virtual_nodes=100):
        if virtual_nodes <= 0:
            raise ValueError("virtual_nodes must be positive")
        self.virtual_nodes = virtual_nodes
        self.ring = []  # Sorted (hash, token, physical-node) tuples.
        self.nodes = set()

    def add_node(self, node):
        # 2) Idempotent membership prevents duplicate virtual-node points.
        if node in self.nodes:
            return
        for index in range(self.virtual_nodes):
            token = f"{node}#{index}"
            self.ring.append((stable_hash(token), token, node))
        self.ring.sort()
        self.nodes.add(node)

    def remove_node(self, node):
        # 3) Remove every virtual point owned by the physical node.
        self.ring = [entry for entry in self.ring if entry[2] != node]
        self.nodes.discard(node)

    def get_node(self, key):
        if not self.ring:
            return None

        # 4) Select the first point clockwise, wrapping at the end of the ring.
        index = bisect.bisect_left(self.ring, (stable_hash(key), "", ""))
        return self.ring[index % len(self.ring)][2]
#include <algorithm>
#include <cstddef>
#include <cstdint>
#include <optional>
#include <stdexcept>
#include <string>
#include <string_view>
#include <unordered_set>
#include <vector>

std::uint32_t stableHash(std::string_view value) {
    // 1) FNV-1a is deterministic across processes; production may use a stronger hash.
    std::uint32_t hash = 2166136261u;
    for (const unsigned char byte : value) {
        hash ^= byte;
        hash *= 16777619u;
    }
    return hash;
}

class HashRing {
public:
    explicit HashRing(std::size_t virtualNodes = 100)
        : virtualNodes_(virtualNodes) {
        if (virtualNodes_ == 0) {
            throw std::invalid_argument("virtualNodes must be positive");
        }
    }

    void addNode(const std::string& node) {
        // 2) Ignore repeated membership updates before adding virtual points.
        if (!nodes_.insert(node).second) return;
        for (std::size_t index = 0; index < virtualNodes_; ++index) {
            const std::string token = node + "#" + std::to_string(index);
            ring_.push_back({stableHash(token), token, node});
        }
        std::sort(ring_.begin(), ring_.end());
    }

    void removeNode(const std::string& node) {
        // 3) Erase all virtual points that belong to the physical node.
        ring_.erase(
            std::remove_if(ring_.begin(), ring_.end(),
                           [&node](const Point& point) { return point.node == node; }),
            ring_.end());
        nodes_.erase(node);
    }

    std::optional<std::string> getNode(std::string_view key) const {
        if (ring_.empty()) return std::nullopt;

        // 4) Binary-search the first clockwise point and wrap past the end.
        const std::uint32_t hash = stableHash(key);
        auto point = std::lower_bound(
            ring_.begin(), ring_.end(), hash,
            [](const Point& entry, std::uint32_t target) {
                return entry.hash < target;
            });
        if (point == ring_.end()) point = ring_.begin();
        return point->node;
    }

private:
    struct Point {
        std::uint32_t hash;
        std::string token;
        std::string node;

        bool operator<(const Point& other) const {
            if (hash != other.hash) return hash < other.hash;
            return token < other.token;  // Deterministic tie-break for collisions.
        }
    };

    std::size_t virtualNodes_;
    std::vector<Point> ring_;
    std::unordered_set<std::string> nodes_;
};
O(log V) lookup; O((V+R) log(V+R)) add; O(V) remove — R = vnodes added

Pitfalls & follow-ups

Without virtual nodes, two physical nodes split the circle terribly unevenly, and removal dumps an entire arc on one survivor. Use a stable hash rather than Python's process-randomized hash(). bisect_left selects the first point at or clockwise from the key; the modulo wrap at the end is the ring. Follow-ups: weighted nodes (more vnodes = more traffic), how this connects to the shard-key discussion in the databases section, and bounded-load consistent hashing.
